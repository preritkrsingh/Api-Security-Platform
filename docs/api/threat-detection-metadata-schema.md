# Threat Detection Request Metadata Schema

This document specifies the telemetry metadata extracted from incoming API requests by the **API Gateway** and forwarded to the **Threat Detection Service** for risk assessment and anomaly detection.

## 1. Security & Privacy First Principle

The Threat Detection Service performs behavioral and statistical anomaly detection (e.g., volumetric spikes, header anomalies, endpoint fuzzing, scanning patterns). It does **not** inspect or store sensitive payload data.

### Strict Redaction & Prohibitions
The following data elements are **strictly prohibited** from being extracted or transmitted to the threat detection engine:
- **No Request or Response Payloads**: Request bodies, form parameters, and JSON payloads are completely omitted.
- **No Authentication Credentials**: Headers such as `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`, `X-API-Key`, or any custom authentication token headers must never have their values transmitted.
- **No Personally Identifiable Information (PII)**: Passwords, email addresses, credit cards, national IDs, and account numbers must never be included.

## 2. Request Metadata Schema (Gateway -> Threat Detection)

The Gateway produces a sanitized JSON object conforming to the following specification:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "ThreatDetectionRequestMetadata",
  "type": "object",
  "required": [
    "requestId",
    "timestamp",
    "clientIp",
    "httpMethod",
    "uriPath",
    "contentLength"
  ],
  "properties": {
    "requestId": {
      "type": "string",
      "format": "uuid",
      "description": "Unique identifier generated by the gateway for request tracing."
    },
    "timestamp": {
      "type": "string",
      "format": "date-time",
      "description": "ISO-8601 UTC timestamp when the gateway received the request."
    },
    "clientIp": {
      "type": "string",
      "description": "Client IP address (or X-Forwarded-For proximate client) used for rate and clustering metrics."
    },
    "httpMethod": {
      "type": "string",
      "enum": ["GET", "POST", "PUT", "DELETE", "PATCH", "HEAD", "OPTIONS"],
      "description": "HTTP request method."
    },
    "uriPath": {
      "type": "string",
      "description": "Normalized URI path (e.g., /api/demo/resource)."
    },
    "queryParamKeys": {
      "type": "array",
      "items": { "type": "string" },
      "description": "List of query parameter names present in the request (values are excluded)."
    },
    "headerKeys": {
      "type": "array",
      "items": { "type": "string" },
      "description": "List of HTTP header names present in the request."
    },
    "userAgent": {
      "type": "string",
      "description": "User-Agent header value for bot and tool fingerprinting (e.g. sqlmap, curl, Mozilla)."
    },
    "contentType": {
      "type": "string",
      "description": "MIME type declared in Content-Type header (e.g., application/json)."
    },
    "contentLength": {
      "type": "integer",
      "minimum": 0,
      "description": "Size in bytes of request payload from Content-Length header (0 if none)."
    },
    "pathDepth": {
      "type": "integer",
      "minimum": 0,
      "description": "Count of path segments to detect traversal or deep scanning."
    },
    "requestFrequency1m": {
      "type": "integer",
      "minimum": 0,
      "description": "Rolling 60-second request count for this clientIp from gateway rate counters."
    }
  }
}
```

## 3. Threat Assessment Response Schema (Threat Detection -> Gateway / Control Plane)

The Threat Detection Service responds with an assessment object:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "ThreatAssessmentResponse",
  "type": "object",
  "required": [
    "requestId",
    "timestamp",
    "riskScore",
    "threatLevel",
    "isAnomaly",
    "recommendedAction"
  ],
  "properties": {
    "requestId": {
      "type": "string",
      "format": "uuid"
    },
    "timestamp": {
      "type": "string",
      "format": "date-time"
    },
    "riskScore": {
      "type": "number",
      "minimum": 0.0,
      "maximum": 1.0,
      "description": "Continuous normalized risk score where 0.0 is benign baseline and 1.0 is highest risk."
    },
    "threatLevel": {
      "type": "string",
      "enum": ["LOW", "MEDIUM", "HIGH", "CRITICAL"],
      "description": "Categorical threat classification based on score thresholds."
    },
    "isAnomaly": {
      "type": "boolean",
      "description": "Flag indicating whether model identified feature space outlier."
    },
    "anomalyScore": {
      "type": "number",
      "description": "Raw decision function score from ML model (e.g. Isolation Forest)."
    },
    "indicators": {
      "type": "array",
      "items": { "type": "string" },
      "description": "Human-readable indicators explaining the score (e.g., UNUSUAL_USER_AGENT, HIGH_REQUEST_VELOCITY)."
    },
    "recommendedAction": {
      "type": "string",
      "enum": ["ALLOW", "LOG", "THROTTLE", "CHALLENGE", "BLOCK"],
      "description": "Policy recommendation for gateway enforcement."
    }
  }
}
```

## 4. Anomaly Detection vs. Confirmed Attack

It is critical to distinguish between:
1. **Statistical Anomaly**: An observation that deviates from learned baseline distributions (e.g. an unusual query key or rapid burst). An anomaly is a potential indicator, not absolute proof of malicious intent.
2. **Confirmed Attack**: Verified exploitation attempts (e.g. known malicious signature or multi-stage exploit).

The platform uses confidence scoring to prevent false positives from disrupting legitimate API clients.
